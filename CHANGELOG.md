# Changelog

Notable changes to the engine and desktop app. Versions follow `cognitive_nexus/version.py`.

## 2.1.0 (unreleased)

### Owner control

What the assistant may say is now the owner's decision, visible in one place. The full account is `docs/OWNER_CONTROL.md`; every mechanism is listed in `docs/OWNER_CONTROL_RESTRICTIONS.md`.

- **The app has one content rule (no sexual content involving minors) and no topic filters.** Removed: a keyword classifier that labelled "how do I kill a stuck process" as harmful and answered such messages with a canned text without asking the model; a block on the letters "child", "cp" and "illegal"; prompt lines telling the model to stay "defensive" and "high level"; a "locked" prompt the persona could not override; a safety slider and checkboxes that changed nothing; and flags named "allow" and "bypass" that added restrictions.
- A model's own refusal is shown as written and marked as the model's. The app used to replace it with a text of its own.
- **Your own messages are never scanned, scored or fenced.** The prompt firewall used to wrap every message you sent as "untrusted" and rate phrases such as "act as" and "from now on" as hostile. It now applies only to text you did not write (web pages, documents, tool output).
- **Settings, Behaviour**: your own text for how the assistant should answer, saved and applied on every turn; the whole system prompt shown word for word; the last prompt exactly as it was sent; what the selected model or its provider may do; and the permissions and protections, each with whether you can change it.
- Three settings with measured consequences: how text from web pages and files is handled (planted instructions obeyed 0, 6 or 7 times out of 12), what the reality check does (label, withhold, or off; it used to withhold detail even in fiction), and how far the coding agent goes unasked.
- The one content rule is checked before anything is written or drawn, and the check was measured with the real model: on requests it was never adjusted on, 36 of 36 forbidden requests were stopped and 43 of 44 ordinary ones answered. The first version of the check stopped 2 of 13; `docs/benchmarks/README.md` has the history.
- **Pictures are held to a stricter line than you asked for**: no picture that would show anyone under 18 nude or undressed, whatever the scene. This is the assistant's own limit, not the owner's rule, and is described as such wherever it appears.
- The greeting no longer claims limits the app does not have.

### Fixed
- **The claim check called a well-known myth likely true.** Checking "Einstein failed math at school" on real pages, it counted two debunking pages as support: they open with the myth ("one of the most repeated bits of trivia: ...", "it's fun to imagine that ...") and reject it after. A sentence that presents the claim as a belief, a saying or something imagined no longer counts as support; a short next sentence that rejects it ("But that's just not true.") makes it count against; and footnote marks, link targets and table rows no longer mislead the rules (Wikipedia's "[1][2]" hid a clause break, so "Everest is the highest mountain above sea level" was read as contradicted). Measured on real pages for 22 claims, eleven of them never used to adjust the rules: `docs/benchmarks/README.md`.
- **An adult request could be stopped by the content rule** when an earlier turn had mentioned a child, and when the judging model answered "Label: NO"; an unreadable answer was then shown as a violation. Earlier turns now count only when the message does not itself settle that only adults are involved, or refers back; "no minors" no longer counts as a mention of minors; "Label: NO" is read; and an unreadable answer is said to be undecided, not a violation. The rule itself is unchanged.
- **Answers came back shorter than asked or were cut off.** The planner never read a stated length, the default "Fast" profile capped every answer at 384 tokens, and nothing looked at why the model stopped. A stated length now sets the budget and outranks the profile, an answer that stops at its limit says so, and when the model itself ends well short of or beyond the length asked for, a note under the answer says so and that the app did not cut it.
- **Simple arithmetic could come back wrong.** It is now worked out exactly by the app; word problems are set up by the model and computed by the app, with the expression shown.
- **Web research searched an ambiguous question as typed** and passed lawn-care pages to a question about cannabis. It now works out what is meant first, has the model judge results that name nothing of the meant sense and drops those about something else, tries a second query when the first is poor, makes one search for the law or availability the answer depends on, and lists names in the answer that no source contains. When the results do not answer the question, the answer says so and then what they do say, instead of stopping at one sentence.
- **The first words of an answer were held back** until 160 characters had arrived (about eight seconds here); they now appear after a few words. Short conversational replies are still held until complete, because stock phrases ("It's great to hear ...") are taken out of them then.
- **The model was reloaded between calls.** The "Fast" speed profile sent `num_batch` 256 with each chat answer, and no other call (the content-rule check, the search plan, the result judge, the web answer) sent it. It is a load-time option, so Ollama reloaded the model at each switch ("runner options changed" in its log). The speed profiles no longer send load-time options.
- The GitHub token was attached to a push to whatever https host a repository's remote named. It is now sent to GitHub only.
- The chat-model list no longer offers embedding models. With `all-minilm` installed for knowledge search, the app picked it as the default chat model, and it cannot chat.
- Chat no longer falls back after 12 seconds on CPU-only machines; Ollama gets at least 120 seconds for the first token and stays loaded between requests.
- Chat web search now runs when asked, answers in under a minute on CPU with sources, and says so when search finds nothing instead of inventing an answer.
- Research verdicts are based on passages that address the claim. "TRUE at 0.8 confidence" from unrelated trusted sites is gone.
- "forget it" no longer deletes unrelated memories; fact ids are stable across launches.
- Deep-mode answers get their intended 780-token budget (a misplaced branch capped them at 420).
- The fallback reply names the provider that failed and why.
- A failed model is no longer saved or shown as an answer: research summaries, knowledge answers and reports show a plain failure notice and store nothing as a "summary". An answer cut off part-way is marked as cut off.
- If the local model fails, the prompt is no longer sent to OpenAI or Anthropic just because a key is configured. Cloud providers are used only when placed first in the provider order or when "Allow cloud fallback" is turned on.
- The Anthropic provider would have failed on every request: its default model (`claude-sonnet-4-20250514`) was retired in June 2026. The default is now `claude-sonnet-5-5`, retired model names in saved settings are replaced automatically, and the request follows the current API. Not yet run against the live API (no key was available).
- A local model whose name starts with "o" (for example `orca-mini`) is no longer sent to OpenAI as a model name.
- Long prompts are no longer cut by the model server. A normal 2,147-token chat prompt was being sent with a 2,048-token window, and Ollama silently kept 1,026 tokens, dropping the instructions. The prompt is now sized in tokens against the model's real window and trimmed in a fixed order, least important first.
- The adaptive memory no longer erases facts saved by "remember ...": it kept its own copy of the profile and wrote it back whole. Its "forget" no longer matches parts of words ("forget it" could erase every memory containing "it").
- Saved memory no longer drops old facts silently at 25 or 60 items; the limit is 500 and reaching it is reported.
- Two programs or tabs saving at the same time no longer overwrite each other's changes (measured before the fix: 22 of 80 concurrent updates survived).
- A web page can no longer give the model instructions. Page text was pasted straight into the prompt, and the local model obeyed 6 of 12 planted instructions ("end every answer with ...", "do not tell the user ..."). Sentences aimed at an AI model are now removed, the rest is fenced as untrusted, and a page cannot forge the end of the fence: 0 of 12 obeyed, with the real facts still answered.
- The claim check no longer counts a passage as support because it shares the claim's words. It compares the same statement: a different figure, a different year for a one-time event, or the opposite word ("fell" for "rose") contradicts; another year of a recurring event, a question, a hedge, an open question or a reported opinion settles nothing; a passage about someone else is not about the claim.
- "Latest version" answers could stay whatever they were when the app started: search results and fetched pages were cached with no expiry. They now expire after 10 and 30 minutes, and failed fetches are not remembered.
- Contradictions between sources were flagged whenever two sentences shared words and one contained "not". They are now found with the claim check's rules, between statements made outright, about the same thing.
- **Making a picture could run the computer out of memory.** The local Stable Diffusion pipeline was loaded beside the chat model, which Ollama keeps in memory for a day; measured here, a 768x768 picture left 0.35 GB free. The app now makes one picture at a time on this computer (a second waits its turn and is told so), and when a picture would not fit beside the chat model it takes the chat model out of memory first and says so under the picture: 8.8 GB stayed free for the same picture. The next chat answer then takes about 12 s longer while Ollama loads the model again; you can choose to keep it loaded instead. A chat request made while a picture is being made no longer loads the model beside it when it would not fit, and a picture stops after 30 minutes instead of running on.

- **Every new connection to the model waited two seconds.** On Windows "localhost" is tried over IPv6 first, and Ollama listens on IPv4 only: each new connection waited 2.05 s for that attempt to fail (0.04 s to 127.0.0.1). The app opened one for every chat answer, because it left each streamed answer before its last bytes were read, which closes the connection. Servers on this computer are now addressed as 127.0.0.1 (saved settings that say "localhost" keep working) and an answer's connection is kept for the next. The app's own share of the time to the first word went from 1.9 to 2.6 s to 0.5 to 0.8 s.
- **Every click in the app waited about 1.7 s** for a ComfyUI server that was not running: the Images tab asked it again on each rerun. The answer is now kept for 30 seconds (running a workflow always asks again), the two image servers are asked at the same time, and Ollama's model list, asked 7 times while the page was first drawn, is asked once and shared for a few seconds. Measured with a stand-in model: first visit 16.0 s with 15 requests, now 5.9 s with 7; each later click 1.8 s, now 0.5 s with none.

- **`streamlit run app.py` let anyone on the network use the app.** Streamlit listens on every network interface unless told otherwise, and the app has no sign-in, so another device on the same network could open it with the owner's full control. `.streamlit/config.toml` keeps it to this computer, as `run.py` and the launcher already did, and turns off the usage statistics Streamlit sends by default. The experimental `fullstack-local` backend accepted calls from any website open in the browser and let it read the answers; it now accepts only its own page.

### Added
- The local picture model is downloaded at the revision it was tested with (`451f4fe1`), not whatever is newest on Hugging Face, so a change pushed there does not arrive unseen; `COGNITIVE_NEXUS_DIFFUSERS_REVISION` chooses another.
- `docs/ACCESS_MODEL.md`: the single-owner access model. Every way in, who can reach it, what it can do, what protects it, what is not protected, and what more than one user would need.
- **Where each sentence of a web answer comes from**, in "How the last answer was made": the page that states it and when it was fetched, or that no page read states it (item 028). By rules, without a model: on labelled sentences it found the page for 27 of 27 that the local model actually wrote and for 8 of 12 written in other words, and let 4 of 22 unsupported sentences through as stated (`docs/benchmarks/claim_map.json`).
- `tools/app_profile.py`: the app's own time and every HTTP request per page draw, click and chat turn, with a stand-in model.
- The coding agent's background queue is bounded: 10 coding tasks (100 jobs of any other kind) may wait at once, and one more is refused with a message instead of piling up; a scheduled job that would go over is skipped with a notice.
- A request for approval in the Agent tab shows exactly what it would do: the tool, its arguments, and the changes on the task's branch it would act on.
- `tools/picture_memory_check.py` measures what a picture costs in memory on this machine, as the app did before and as it does now.
- Search sources with automatic switching (SearXNG, Brave Search API, search pages, Wikipedia).
- Refusal to fetch local and private-network addresses during research.
- Crash-safe (atomic) saves for memory, settings and the knowledge index.
- Local image generation downloads 2.0 GB instead of 5.1 GB.
- Continuous integration: tests on Windows and Ubuntu, lint, type check, secret scan, dependency audit.
- `docs/STATUS.md`, the audit ledger (`docs/AUDIT_146_PROGRESS.md`) and pinned dependencies (`requirements/constraints.txt`).
- Every reply is labelled with who wrote it (provider and model, or no model), whether the prompt stayed on this machine, the time taken, the cost when a cloud provider reports usage, and the tools that ran.
- The chat model is checked with a real test prompt at start; Diagnostics can send a test prompt to any provider and shows a provider as working only after it has produced text.
- Diagnostics counts model failures, fallback notices, search-source failures and tool failures separately (also written to `logs/events.jsonl`).
- Cloud calls retry rate limits and dropped connections and report the provider's own error message.
- Saved facts record how each is known (instruction, preference, stated fact, or inferred by the app), when it was first said and last confirmed. A new value replaces the old one and keeps it as history ("remember also:" keeps both); "remember for 3 days that ..." expires; "forget ..." also removes earlier values, related preferences and the copies in local snapshots.
- "Your data" in the Memory tab, and `python tools/data_tool.py`: export, passphrase-encrypted backup, verified restore with undo, daily local snapshots, repair of a damaged file from a snapshot, and permanent selective wipe. `docs/DATA_STORES.md` lists everything the app saves.
- `COGNITIVE_NEXUS_HOME` keeps all saved data outside the project folder.
- The summary of older chat turns covers the whole conversation and keeps decisions, numbers and file names rather than the last 18 messages.
- Diagnostics shows how the last prompt was fitted to the model's context window.
- **A project dashboard at the top of the Agent tab** (item 140): the milestones (one per section of the 146-item audit, with how much of each is done), the build (the agent's last test runs, and GitHub's workflow runs and newest commits for the branch while a switch is on), active bugs, the agent's progress with the time and attempts each open task has used, a time estimate from the project's finished tasks, and the newest commits. In demo-safe mode it shows no path and looks nothing up.
- **The coding agent has a memory for each project** (item 048): objectives, decisions and known bugs you write down (Agent tab, or `python -m agent memory add`), and the last result of each test command and the repository's state, which the agent records as it works. It is shown what is known before every attempt, your notes marked as yours; a closed note stays in the history.
- **NexusCore is built from five service classes in their own modules** (item 121, partly): how a model is asked, building the chat prompt, finishing an answer, research outside the chat, and pictures. modules/nexus_core.py went from 2,088 lines to 1,139; every method keeps its name and works as before. The chat turn itself (`stream_chat_response`, about 800 lines) is still one method.
- **Each tab is drawn by its own module under `ui/`** (item 120). app.py was 2,609 lines with every tab in it; it now only starts the app and lays out the tabs (152 lines), and each tab can be drawn and tested on its own. Each click is faster (a rerun took 0.47 to 0.54 s, now 0.22 to 0.29 s) because Streamlit runs app.py again on every click and the tabs' code is now imported once.
- **Keys and tokens are kept out of the app's own records** (item 110). The log file, the event log, the answer checks and the metadata saved with pictures (including the workflow a ComfyUI picture carries inside it, where a custom node can hold a key) are redacted as they are written: key and token shapes, passwords and keys in web addresses, Authorization values, and this machine's own secrets. The owner's chat, the prompts sent to the model and the answers are not changed. `python tools/check_repo_hygiene.py --scan logs data app-release.apk` checks older logs or a phone build, inside the archive too.
- **A story retold in other words on several sites counts once** in a claim check (item 030). Passages that take the same side are compared by meaning with the `all-minilm` embedding model when it is installed; on pairs never used to set the threshold, 9 of 10 retellings were counted once and none of 10 independent reports were merged. The report lists what was counted once and says when the comparison could not be made; the Research tab has an option to turn it off.
- Claim checks show their working: why each passage was counted, when the page was retrieved and published, which sources did not address the claim, and which were repeats of a site or passage already counted. When supporting and contradicting pages have different dates, the report says which is newer.
- The model re-reads each passage the rules count as supporting a claim, and the passage counts only if both agree (a setting; a few seconds per passage). Measured on unseen passages: false support 5 of 30 without it, 3 of 30 with it.
- Research answers flag links that were not among the retrieved pages, in addition to version numbers and years that are not in the sources.
- Fetching pages: one retry for a dropped connection or a busy server, a pause between requests to the same site, the same page under two addresses fetched once, and copies of one article on several sites marked as one source.
- Measured results in `docs/benchmarks`, each with the tool that produced it: hidden instructions in pages, the claim check on four labelled sets (two of them never used to adjust it), and research answers on frozen pages. Saved results carry a fingerprint of the prompt they were measured with, and a test fails when the app's prompt changes without a new measurement.
- **Answering with tools** (`python -m agent ask "..."`). The local model has no tool calls of its own, so each step is one JSON object that the model server holds to a schema: search the web, read a page (and follow its links), search your notes, or answer. Every call is checked and recorded like any other action. Two rules about where your data may go apply in such a run: after your own notes were read nothing more is sent out, and a page is fetched only if its address came from your request, a search or a page already read. Measured with the local 8B model on requests it was not tuned on: the right tool in 11 of 12.
- **What it can do, in one list** (Agent tab, or `python -m agent tools`): every tool with what it takes, returns, can affect and needs; the apps found on this machine; linked accounts and what each may be used for. A tool that cannot be used right now says what is missing.
- **What the model can do** (`python -m agent model`, and the Agent tab): context length, tool calls, structured output, vision, with where each answer comes from. "Not known" is never treated as yes.
- **A change to the app is measured before it replaces what was there** (`tools/evaluation_gate.py`). The coding agent's changes to this app's own code can only be accepted after that comparison came out not worse, or with a stated reason.
- **Linked accounts** (Settings, or `python -m agent accounts`). A token or key can be stored from the app instead of an environment variable: encrypted for your Windows user, never shown again, never part of a backup, export or snapshot. Linking allows nothing by itself: you tick what each account may be used for (GitHub: read, push, pull request), and can withdraw one use or unlink. A credential with an expiry is renewed where the service allows it and refused, with the reason, where it does not. Keys in environment variables keep working, and a use can be withheld from those too.
- **Agent tab.** Give the coding agent a repository and a failing test, start it or hand it to the background worker, see what waits for you (requests for approval, changes to accept or send back, with the diff), every action it took with inputs and checked results, background jobs, and every tool with what it can affect.
- The coding agent sets up what a repository needs: a virtual environment per task inside the sandbox, with the packages named in the repository's own requirement files, from a download cache. By default only ready-made packages are installed (no build scripts run), a requirement file the task itself changed is not trusted, and `pip install` typed as a command is still refused. Settings, Behaviour has the choice (declared files only, anything, nothing).
- The coding agent was measured on a second set of seeded bugs that nothing had been tuned on: 4 of 9 fixed with the local 8B model, against 7 of 9 on the first set. The lower figure is the one the app now quotes. No failure was reported as a success in either run.
- Foundations for an agent that acts (`agent/`): a registry in which every tool has a schema and a declared effect; approvals by effect, with anything that reaches outside the machine always needing one; a history of every action with its inputs, approval and checked result; tasks with owner, status, dependencies and acceptance tests; a sandbox for running programs with a clean environment, memory, process and time limits and, on Windows, writes refused outside the task folder; a private Git worktree and branch per task; and tools to read, search, edit with undo, run tests and commit.
